## Current App State

**What works:**
- Full Docker stack runs and all three containers are healthy
- API health check: `GET /api/v1/health` → `{"status":"healthy"}`
- Auth: login/register/Google sign-in. Access token is held in-memory by `AuthStore` (no localStorage); refresh token is an httpOnly cookie. `authInterceptor` attaches `Bearer` from the store and refreshes on 401. Silent refresh on app init hydrates the session from the cookie. `authGuard`/`guestGuard` protect routes.
- State: `AuthStore`, `DashboardStore`, `AccountsStore` built as NgRx SignalStores with feature-file split (state/computed/methods/effects/store)
- Vitest unit tests covering the signal stores (run with `npx ng test --watch=false`)
- All bank-sync pages render (accounts list, connect, transactions, dashboard)
- Backend: accounts, transactions, sync, webhook, dashboard endpoints all implemented
- Data retention & backups (024): `FinanceSentry.Modules.Retention` (schema `retention`). A compiled `RetentionPolicyRegistry` gives every table a purge/downsample/keep decision (reflection coverage-guard + keep-forever whitelist tests). Nightly `retention-purge` batch-deletes out-of-policy rows idempotently; nightly `db-backup` does `pg_dump → age-encrypt → Cloudflare R2`; weekly `db-restore-verify` restores into an isolated scratch DB and marks the artifact Verified. US3 `retention-downsample` (weekly compaction) is gated off (`Retention:Downsample:Enabled`). Ops verbs: `dotnet FinanceSentry.API.dll retention-purge [--dry-run] | db-backup | db-restore-verify`. R2/age secrets in `.env.sops` (`BACKUP_*`); blank = jobs no-op. Grafana dashboard `retention-backups`.

**Broad-universe opportunity scanning (#558) — two-stage funnel, enabled in the API host.** The scan universe is no longer held-positions ∪ watchlist, and it is not the whole index either. **Stage 1 (Research, mechanical):** `ScanShortlistService` ranks the checked-in S&P 500 seed on two cheap signals — the day's percent change from the batch quote read and recent favourable street actions (upgrades, new coverage, target *raises*) over `Opportunity:ScanShortlistActionLookbackDays` — grades the top `Opportunity:ScanShortlistGradeBudget` (60) through EDGAR, and hands back the top `Opportunity:ScanShortlistSize` (40) by combined quality x surface score. No bars are read to produce it; every upstream may fail, and if they all do the shortlist is empty. **Stage 2 (Radar, expensive):** `Radar:BroadUniverseEnabled` (set `true` in `backend/src/FinanceSentry.API/appsettings.json`; override with `Radar__BroadUniverseEnabled=true`) makes `RadarUniverseService` append *that shortlist* as `UniverseKind.IndexConstituent` members — ownership kinds still win, so a shortlisted name you hold stays a `Holding`. The nightly `radar-ingestion` job fetches bars for exactly the active universe (book + lenses + shortlist, tens of tickers), `MarketStructureReader` computes structure for the same set, and `OpportunityScanJob` ranks it by quality x momentum (`Opportunity:ScanQualityWeight`). There is no ingestion budget and no rotation any more: the shortlist *is* the bound, pinned by `ShortlistScopedIngestionTests` and `ShortlistStructureCostTests`. The shortlist churns daily and dropped members are de-activated by the usual compose-and-deactivate path; constituents stay exempt from `RadarFreshnessWatchdogJob` (a name shortlisted today has no bars until the run that ingests it). **Turning it off** is the same key set to `false`: the next sync deactivates the shortlisted members, stage 1 is never asked for a shortlist, and the scanner falls back to the book. The seed list (`Modules.Research/Infrastructure/Resources/sp500-constituents.json`) is regenerated from the public constituents dataset and every symbol verified against the Yahoo chart endpoint — symbols are stored in Yahoo form (`BRK-B`, not `BRK.B`); never hand-edit it. **Alert fan-out** is gated the way Radar's structure scanner launched: `Opportunity:ScanAlertMode` ships `LogOnly` (set in `appsettings.json`; override with `Opportunity__ScanAlertMode=Alerting`), so a top-tier *Scan* nomination records its `top_tier_candidate` signal but raises no Alert — a widened scan clearing the bar on several unfamiliar names would otherwise interrupt once per name per user. User and Ledger nominations are deliberate acts and alert regardless. `Opportunity:ScanMaxNominationsPerRun` is 8 (was 5, set against the whole-index width); the top-decile cut stays 90 — the percentile is inclusive, so its absolute yield already shrinks with the universe. Still open (US6): a genuinely batched quote read for stage 1 (today it costs ~500 light per-ticker quote fetches a night), and keeping an active Scan candidate's bars fresh once its ticker drops off the shortlist. Spec: `specs/20260910-001634-broad-universe-scan/`.

**Intraday-move detector (ledger-heartbeat P1) — DONE.** Hangfire job `intraday-move-sentinel` (every 15 min, `IntradayMoveSentinelJob` in `FinanceSentry.Modules.Research/Infrastructure/Jobs/`) reads prices for every held equity (`STK`), held crypto asset (`{Asset}-USD`, venue fiat excluded) and watchlist ticker through `IMarketDataService.GetQuotesAsync` — the existing 5-minute Yahoo quote cache, no new live-price fetch path — and raises a Warning `AlertType.MarketStructure` (the same type/companion mapping the nightly Radar unusual-move check already uses) when a holding moves ≥5%, a watchlist ticker moves ≥8% (a ticker held **and** watchlisted keeps the holding's 5% bar), or either moves ≥3σ against the standard deviation of its last 20 daily returns (`IMarketDataService.GetDailyClosesAsync`, only called when the plain move threshold didn't already fire, at most once per ticker per run, with today's in-progress bar excluded; fewer than 21 prior closes makes the z-score not evaluable — never fires on a thin sample). Yahoo's chart endpoint reports no `marketState`, so market hours are an explicit NYSE regular-session check (weekday 09:30–16:00 America/New_York) plus the quote's `RegularMarketTime` falling on today's New York date (keeps exchange holidays quiet); a held crypto asset has no exchange session and is evaluated on every tick while its `SourcePriceTime` is under an hour old. The quote's `PreviousClose` is the prior session's daily bar (not the 5-day chart's `chartPreviousClose`, which is a weekly baseline). A stale, missing or malformed quote is skipped — never an alert, never a job failure. The alert reference id is a deterministic per-ticker hash (independent of the nightly Radar checker's own reference), and the job passes `AlertDedup.SilenceOnly` to `GenerateMarketStructureAlertAsync` so only its 24-hour silence window applies (an unread earlier alert does not suppress a later move; the nightly Radar caller keeps the default `ActiveThenSilence`), so a name that keeps moving announces itself once a day, not once every 15 minutes. Past its window, the intraday re-fire resolves the still-open earlier alert on that ticker before inserting (only the market-structure `SilenceOnly` path opts in). Follow-up (pre-existing, out of scope): a second `JobFailure` streak for the same job while the first alert is still open still collides with `idx_alert_dedup` and throws.
